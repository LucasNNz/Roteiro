CORVOQUIZ — CONFIGURAÇÃO CLOUDFLARE R2
VERSION=1.1
APP=V0.6.37

VARIÁVEIS NA VERCEL
====================

Cadastre exatamente estas variáveis no projeto roteiro:

R2_ACCOUNT_ID=<Account ID da Cloudflare>
R2_ACCESS_KEY_ID=<Access Key ID do token R2>
R2_SECRET_ACCESS_KEY=<Secret Access Key do token R2>
R2_BUCKET_NAME=<nome do bucket, por exemplo corvoquiz>
R2_ENDPOINT=<endpoint S3 fornecido pela Cloudflare, por exemplo https://ACCOUNT_ID.r2.cloudflarestorage.com>

Nenhuma variável adicional é obrigatória.

CONFIGURAÇÃO DESTE PROJETO
==========================
R2_BUCKET_NAME=corvoquiz-prod
R2_ENDPOINT=https://34da8bbc6302e3c68edf3a36f1569668.r2.cloudflarestorage.com

ATENÇÃO: cada valor deve ocupar UMA única linha. Não repita corvoquiz-prod dentro da mesma Environment Variable.

O CorvoQuiz usa 7 dias como TTL padrão das URLs assinadas.
Se quiser alterar:
R2_SIGNED_URL_TTL_SECONDS=<60 até 604800>

IMPORTANTE
==========
- Não use NEXT_PUBLIC_ nas credenciais.
- O token R2 deve ter Object Read & Write no bucket.
- R2_BUCKET_NAME é o nome oficial usado pelo kit V0.6.37.
- R2_BUCKET antigo continua aceito apenas para compatibilidade.
- R2_ENDPOINT deve ser o endpoint S3 BASE, sem /bucket no final. A V0.6.37 remove /bucket automaticamente como proteção.

DIAGNÓSTICO V0.6.37
--------------------
O app usa AWS SDK v3 oficial para S3/R2.
Antes do Collector, /api/corvo/diagnostico executa:
R2_ENDPOINT_OK -> R2_DNS_OK -> R2_BUCKET_OK (quando permitido) -> R2_WRITE_OK -> R2_READ_OK -> R2_DELETE_OK

Se HeadBucket for bloqueado por um token restrito, o app ainda tenta PUT/GET, que são a validação definitiva do fluxo de arquivos.
Nenhum diagnóstico retorna R2_ACCESS_KEY_ID ou R2_SECRET_ACCESS_KEY.
