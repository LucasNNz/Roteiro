CORVOQUIZ — ESPECIFICAÇÃO DE ATUALIZAÇÃO DO APP / BRIDGE
VERSION=1.0
DATA=2026-08-15

OBJETIVO DESTE DOCUMENTO
========================

Este TXT reúne as decisões tomadas para a próxima evolução do fluxo do CorvoQuiz.

Ele deve servir como documento de contexto para o modificador/programador do app, explicando:

- o fluxo atualizado de imagens;
- a divisão entre Analista, Refinador, Gerador e Fallback;
- a criação paralela da thumbnail;
- o futuro GPT de dados/metadados para YouTube;
- o comportamento esperado do CORVO BRIDGE;
- a captura da thumbnail gerada na conversa;
- a necessidade de novos endereços de GPTs personalizados no app;
- a consolidação final de imagens via merge de ZIP;
- os contratos/manifestos usados pelos GPTs;
- os schemas atuais das Actions;
- as regras de espera e conclusão de jobs longos;
- a arquitetura preparada para futura publicação automática no YouTube.

==================================================
1. VISÃO GERAL DO NOVO FLUXO
==================================================

O pipeline principal passa a ser:

IDEIA / TÍTULO
↓
ROTEIRO
↓
CORVO COLLECTOR
↓
CORVO ANALISTA DE IMAGENS
↓
RAMIFICAÇÃO PRINCIPAL DE IMAGENS

PASSOU / PASSOU_COM_RESSALVAS
→ CORVO REFINADOR
→ IMAGENS FINAIS DO RAMO COLLECTOR

NAO_PASSOU
→ CORVO GERADOR DE IMAGENS
→ IMAGENS FINAIS GERADAS

SE GERADOR OU REFINADOR FALHAR
→ ERROR_CODE + MOTIVO
→ APP
→ CORVO FALLBACK
→ RETRY OU NAO_RECUPERAVEL

DEPOIS:
IMAGENS FINAIS DO REFINADOR
+
IMAGENS FINAIS DO GERADOR
→ APP
→ MERGE DOS ARQUIVOS
→ ZIP FINAL
→ FORMA

IMPORTANTE:
A imagem produzida pelo GERADOR já é FINAL.
Ela NÃO precisa passar novamente pelo REFINADOR.

A imagem produzida pelo REFINADOR também é FINAL.

O app apenas une os dois ramos ao final.

==================================================
2. RAMIFICAÇÕES PARALELAS AO INICIAR O COLLECTOR
==================================================

Quando o app iniciar o CORVO COLLECTOR, ele já pode abrir ramificações paralelas para outras tarefas que não precisam esperar o fluxo completo das imagens.

Fluxo sugerido:

INICIAR PRODUÇÃO
↓
CORVO COLLECTOR
│
├── RAMO A → PIPELINE DE IMAGENS
│             COLLECTOR
│             → ANALISTA
│             → REFINADOR / GERADOR
│             → FALLBACK quando necessário
│             → MERGE ZIP
│
├── RAMO B → CORVO THUMB
│             recebe título/ideia/contexto
│             → cria thumbnail
│             → Bridge captura imagem
│             → app salva thumb
│
└── RAMO C → FUTURO CORVO YOUTUBE / METADADOS
              recebe título/ideia/roteiro/contexto
              → cria dados de publicação

Esses ramos não precisam bloquear uns aos outros.

A ideia é aproveitar o tempo em que Collector, Analista, Refinador e Gerador estão trabalhando para adiantar:

- thumbnail;
- título refinado;
- descrição;
- tags;
- hashtags;
- categoria;
- horário sugerido;
- data sugerida;
- demais dados de publicação.

==================================================
3. NOVOS GPTs PERSONALIZADOS / ENDEREÇOS NO BRIDGE
==================================================

O app/Bridge precisa ter, no mínimo, mais 4 campos/endpoints/configurações para endereços de GPTs personalizados:

1. CORVO GERADOR DE IMAGENS
2. CORVO THUMB
3. CORVO FALLBACK
4. CORVO YOUTUBE / DADOS PARA YOUTUBE

Esses quatro devem ser configuráveis no app.

Sugestão de configuração:

GPT_URL_GERADOR=
GPT_URL_THUMB=
GPT_URL_FALLBACK=
GPT_URL_YOUTUBE=

Não hardcodar URLs de GPT diretamente no código sempre que possível.

Ideal:
Configurações > GPTs / Especialistas

Campos:

- Collector
- Analista
- Refinador
- Gerador
- Fallback
- Thumb
- YouTube / Metadados

Assim cada especialista pode ser trocado sem modificar o código do app.

==================================================
4. CORVO ANALISTA DE IMAGENS
==================================================

O Analista continua sendo o roteador principal das imagens coletadas.

Classificações:

PASSOU
→ REFINAMENTO=LEVE

PASSOU_COM_RESSALVAS
→ REFINAMENTO=FORTE

NAO_PASSOU
→ PROMPT_GERACAO
→ GERADOR DE IMAGENS

Manifesto base:

[CORVO_IMAGE_ANALYSIS]
VERSION=1.0

[TOTAL]
IDS=<total>
PASSOU=<quantidade>
PASSOU_COM_RESSALVAS=<quantidade>
NAO_PASSOU=<quantidade>

[ID:<id>]
STATUS=PASSOU
ARQUIVO=<arquivo real>
MOTIVO=<motivo>
REFINAMENTO=LEVE

[ID:<id>]
STATUS=PASSOU_COM_RESSALVAS
ARQUIVO=<arquivo real>
MOTIVO=<motivo>
REFINAMENTO=FORTE

[ID:<id>]
STATUS=NAO_PASSOU
ARQUIVO=
MOTIVO=<motivo>
PROMPT_GERACAO=<prompt completo>

[END]

O app deve interpretar este manifesto e dividir automaticamente os IDs.

==================================================
5. CORVO REFINADOR DE IMAGENS
==================================================

O Refinador recebe apenas imagens aprovadas pelo Analista.

PASSOU
→ refinamento leve

PASSOU_COM_RESSALVAS
→ refinamento forte

Ele deve:

- preservar identidade;
- melhorar nitidez;
- melhorar resolução;
- melhorar contraste;
- melhorar iluminação;
- melhorar cor;
- melhorar enquadramento;
- adaptar para 16:9 quando necessário;
- reduzir ruído e artefatos;
- ampliar o elemento principal quando necessário;
- entregar imagem FINAL.

O Refinador não deve:

- trocar personagem;
- trocar jogo;
- trocar objeto;
- mudar conceito visual;
- criar livremente outra cena.

Status possíveis:

REFINADA
FALHOU

Manifesto atual:

[CORVO_IMAGE_REFINEMENT]
VERSION=1.1

[TOTAL]
IDS=<total>
REFINADAS=<quantidade>
FALHOU=<quantidade>

[ID:<id>]
STATUS=REFINADA
ARQUIVO=<arquivo final>

[ID:<id>]
STATUS=FALHOU
ARQUIVO=
ERROR_CODE=<codigo>
MOTIVO=<motivo curto>

[END]

ERROR_CODE possíveis:

POLICY_BLOCK
EDIT_BLOCK
TOOL_ERROR
INVALID_OUTPUT
IDENTITY_LOST
FILE_ERROR
UNKNOWN_ERROR

Se FALHOU:
o app pode encaminhar esse ID para o CORVO FALLBACK.

==================================================
9. CORVO FALLBACK
==================================================

O Fallback é o especialista de recuperação de falhas.

Ele NÃO:

- gera imagem;
- edita imagem;
- procura arquivo;
- executa retry diretamente.

Ele recebe:

ID
ORIGEM
ERROR_CODE
MOTIVO
PROMPT_ORIGINAL / INSTRUCAO_ORIGINAL
CONTEXTO
IDENTIDADE
TENTATIVA_ATUAL

ORIGEM:

GERADOR
ou
REFINADOR

Ele decide:

RETRY
ou
NAO_RECUPERAVEL

Se RETRY:

STATUS=RETRY
DESTINO=<GERADOR ou REFINADOR>
PROMPT_RETRY=<nova solicitação>

Se NAO_RECUPERAVEL:

STATUS=NAO_RECUPERAVEL
DESTINO=
MOTIVO=<motivo>

Fluxo:

GERADOR / REFINADOR
→ FALHOU + ERROR_CODE
→ APP
→ FALLBACK

Se RETRY:
→ app cria nova tentativa para DESTINO

Se NAO_RECUPERAVEL:
→ app marca para tratamento manual/técnico

IMPORTANTE:
Fallback não existe para burlar política.
POLICY_BLOCK deve ser tratado criando apenas alternativa legítima quando houver.
Se não houver alternativa válida:
NAO_RECUPERAVEL.

FILE_ERROR normalmente deve virar NAO_RECUPERAVEL quando o problema é arquivo ausente/inacessível.

12. CORVO THUMB
==================================================

CORVO THUMB recebe:

IDEIA
TITULO / TITULO_BASE
TEMA
ROTEIRO ou RESUMO
TIPO_DE_QUIZ
PUBLICO
IDENTIDADE_VISUAL
MASCOTE
IMAGENS DE REFERENCIA quando houver
PADRAO_ARQUIVO_FINAL

Ele:

1. entende a promessa do vídeo;
2. define conceito visual;
3. decide se texto ajuda;
4. gera efetivamente UMA thumbnail;
5. deixa a imagem disponível na conversa;
6. entrega manifesto ao Bridge.

A thumbnail deve:

- ser 16:9;
- ter leitura rápida;
- ter poucos elementos;
- complementar o título;
- não repetir o título inteiro;
- não enganar;
- manter identidade CorvoQuiz;
- poder usar texto curto, mas texto é opcional.

Status:

GERADA
FALHOU

Manifesto atual:

[CORVO_THUMBNAIL]
VERSION=1.1

STATUS=GERADA
ARQUIVO=<arquivo final>
TIPO_ARQUIVO=THUMBNAIL
CONCEITO=<resumo curto>
TEXTO_THUMB=<texto ou vazio>

[END]

Falha:

[CORVO_THUMBNAIL]
VERSION=1.1

STATUS=FALHOU
ARQUIVO=
ERROR_CODE=<codigo>
MOTIVO=<motivo curto>

[END]

==================================================
13. CAPTURA DA THUMB PELO CORVO BRIDGE
==================================================

PONTO MUITO IMPORTANTE:

A Action entregarResultadoCorvo envia somente o manifesto.
Ela NÃO envia os bytes da imagem.

Por isso o CORVO BRIDGE deve ser atualizado para capturar a imagem gerada pelo GPT.

Fluxo desejado:

CORVO THUMB
→ gera imagem
→ imagem aparece na conversa
→ manifesto informa:
   ARQUIVO=thumb_xxx.png
   TIPO_ARQUIVO=THUMBNAIL
→ Bridge detecta a imagem gerada
→ Bridge captura/download/blob da imagem
→ Bridge renomeia de acordo com ARQUIVO
→ Bridge envia arquivo ao app
→ app associa o arquivo ao JOB_ID

Sugestão de endpoint no app:

POST /api/corvo/arquivo

Dados esperados conceitualmente:

jobId
tipo
nomeArquivo
arquivo

Para thumbnail:

tipo=THUMBNAIL

Sugestão de estado do job:

resultadoRecebido=true/false
arquivoRecebido=true/false

Para STATUS=GERADA, considerar job realmente concluído somente quando:

resultadoRecebido=true
E
arquivoRecebido=true

Isso evita:

STATUS=GERADA
ARQUIVO=thumb.png

sem a existência real de thumb.png no app.

IMPORTANTE:
O GPT não faz upload manual.
O Bridge é quem captura a imagem da conversa.

16. ESPERA LONGA / JOBS ASSÍNCRONOS
==================================================

A aba de Merge e o pipeline de imagens precisam aceitar espera prolongada.

Gerador, Refinador e Fallback podem levar bastante tempo.

Não usar uma lógica que considere falha apenas porque demorou alguns segundos/minutos.

Sugestão:

estado por job:

PENDENTE
ENVIADO
PROCESSANDO
AGUARDANDO_RESULTADO
RESULTADO_RECEBIDO
AGUARDANDO_ARQUIVO
CONCLUIDO
FALHOU
EXPIRADO

A UI deve poder ficar aberta acompanhando jobs longos.

Importante:

- não destruir job ao recarregar página;
- persistir jobId;
- persistir especialista;
- persistir IDs;
- persistir tentativa atual;
- persistir status;
- persistir horário de início;
- permitir retomar monitoramento;
- distinguir timeout local da expiração real do servidor.

A aba de Merge deve poder ficar "AGUARDANDO" por tempo extenso até os dois ramos terminarem.

Exemplo:

REFINADOR: 44/44 CONCLUÍDAS
GERADOR: 13/16 CONCLUÍDAS
FALLBACK: 2 EM RECUPERAÇÃO
MERGE: AGUARDANDO

17. FALLBACK E CONTROLE DE TENTATIVAS NO APP
==================================================

O app deve controlar retries.

Sugestão inicial:

MAX_RETRIES=2

Fluxo:

TENTATIVA 1
→ falhou
→ FALLBACK
→ RETRY
→ TENTATIVA 2

Se falhar novamente:
→ FALLBACK
→ se ainda RETRY e limite permitir
→ nova tentativa

Se atingir limite:
→ marcar FALHA_FINAL / TRATAMENTO_MANUAL

O GPT FALLBACK não controla o limite.

O app deve salvar:

id
origem
errorCode
motivo
promptOriginal
promptRetry
tentativaAtual
destino
historicoTentativas

Isso cria trilha de auditoria.

21. BRIDGE — RESPONSABILIDADES ATUALIZADAS
==================================================

O CORVO BRIDGE passa a ter responsabilidades mais claras:

1. abrir/iniciar a conversa correta do especialista;
2. enviar CORVO_BRIDGE_JOB;
3. preservar JOB_ID;
4. aguardar a Action entregarResultadoCorvo;
5. receber status/manifesto pelo app;
6. controlar ramificações paralelas;
7. acionar Fallback quando necessário;
8. capturar imagem visual gerada pelo CORVO THUMB;
9. enviar a thumb real ao app;
10. associar arquivo ao JOB_ID;
11. manter estados dos jobs;
12. permitir espera longa;
13. não misturar arquivos entre jobs;
14. não considerar STATUS=GERADA como suficiente se o arquivo real ainda não chegou.
